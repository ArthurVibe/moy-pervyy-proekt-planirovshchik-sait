## Реализация и параметры

Добавлены три декоративных слоя внутри `.hero-scene`: чёрное затемнение и два радиальных свечения. Их общий контейнер ограничен прямоугольником фотографии, имеет `pointer-events: none` и `aria-hidden="true"`. Размеры существующих элементов не меняются.

| Источник | X / Y в оригинале 2560 × 1440 | Радиус в оригинале | Максимальная opacity | Начало свечения |
|---|---|---:|---:|---:|
| Левое бра | 196 / 262 | 260 px | 0,12 | 250 мс |
| Правый торшер | 2200 / 430 | 250 px | 0,11 | 400 мс |

Координаты визуально сверены с исходной фотографией. Для каждого источника есть отдельные CSS-переменные `--club-left/right-x`, `-y`, `-radius`, `-strength`. Тёплый градиент использует RGB 255/219/157, 229/170/95 и 182/116/56 с прозрачными краями; смешивание — `screen`.

Затемнение составляет 18% в первые 250 мс, уменьшается до 2,5% к 1200 мс и до нуля к 1800 мс. Левое свечение достигает максимума к 900 мс, правое — к 1050 мс; с 1200 до 1800 мс оба исчезают. В покое opacity всех новых слоёв равна нулю.

Правая маска полностью исключает свечение при X ≤ 2010 и плавно открывает его до X = 2070 исходного изображения. Независимая проверка свечения на максимуме дала **0 изменённых пикселей в полосе Bro X 1550–2010**. Общее начальное затемнение применяется ко всей фотографии согласно ТЗ.

Положение вычисляется по фактическому прямоугольнику изображения, `naturalWidth/Height`, масштабу `cover` и обоим компонентам `object-position`. Для процентного положения используется смещение `(размер контейнера − размер масштабированного изображения) × доля object-position`. Радиусы масштабируются вместе с фотографией. При выходе центра лампы за кадр её слой скрывается.

| Viewport | Левое бра: центр / радиус, CSS px | Правый торшер: центр / радиус, CSS px |
|---|---|---|
| 1440 × 900 | 58,50 / 163,75; r 162,50 | 1311,00 / 268,75; r 156,25 |
| 1280 × 800 | 52,00 / 145,56; r 144,44 | 1165,33 / 238,89; r 138,89 |
| 1024 × 768 | Вне кадра, выключено | 941,23 / 229,33; r 133,33 |
| 390 × 844 | Вне кадра, выключено | 359,23 / 116,46; r 67,71 |
| 360 × 800 | Вне кадра, выключено | 331,60 / 107,50; r 62,50 |

Координаты в таблице отсчитываются от верхнего левого угла фотографии. На мобильном блок фотографии расположен ниже текста; свет не выходит за его пределы. `ResizeObserver` обновляет только координаты при изменении размеров и отключается после завершения. Анимация при resize не перезапускается.

Ранний скрипт до первой отрисовки готовит приглушённое состояние только при разрешённой анимации. Запуск происходит после `load` и успешного `decode()` изображения. Если готовность не наступила за 1500 мс от начала навигации, состояние сбрасывается; позднее фото появляется с обычным освещением. Исходный `fetchpriority="high"`, `<picture>`, пути и декодирование фотографии сохранены.

Наведение на Meet Bro, клавиатурный фокус и начало прокрутки переводят новые слои в нулевую прозрачность за 160 мс; в проверках полное завершение занимало 161–163 мс. Warm Welcome работает по исходным правилам. При reduced motion новые слои немедленно становятся прозрачными через CSS, обработчик отменяет вступление, и последующее отключение reduced motion не запускает его заново.

При скрытии активной вкладки и `pagehide` эффект завершается. Изначально скрытая вкладка может начать его после показа только в пределах исходного окна 1500 мс. Обычное обновление страницы допускает новый запуск; возврат из bfcache — нет. `sessionStorage`, новые запросы и новые библиотеки не используются.

## Проверки и производительность

- Chromium 154.0.8037.57, Linux: **22 проверки поведения прошли**, включая независимые URL-параметры, отключённый JavaScript, ошибку фото и ошибку JS, отсутствие основного контроллера, готовность фото до/после дедлайна, кеш, обновление, взаимодействие, resize и reduced motion.
- Реальный возврат из bfcache прошёл с `pageshow.persisted === true`; повторного вступления нет. Скрытие/показ вкладки проверены эмуляцией `hidden`, `visibilityState` и `visibilitychange` в тестовом окружении.
- При повторной загрузке фотография получена из кеша: `deliveryType: cache`, `transferSize: 0`; выполнен один новый запуск на обновление.
- Мобильное меню, Get Early Access, закрытие меню и Coming soon доступны во время вступления; декоративные слои не перехватывают нажатия.
- Во всех пяти viewport геометрия 20 существующих элементов совпала с базой; горизонтальной прокрутки нет.
- В каждом viewport и для `clubLights=off`, и для завершённого `on` получено **0 отличающихся пикселей** от исходного коммита. Мобильный интерфейс над фотографией также совпал с базой в фазах 0 и 600 мс.
- Зафиксированных новых ошибок JavaScript в обычных сценариях нет. Ожидаемая ошибка в отдельном тесте проверяет аварийное восстановление. Прежний запрос браузера к отсутствующему favicon не изменялся.

Пять чередующихся холодных запусков каждого режима на локальном HTTP, без ограничения CPU:

| Viewport | Медиана LCP базы | Медиана LCP эффекта | Максимальный CLS, оба режима |
|---|---:|---:|---:|
| 1440 × 900 | 712 мс | 732 мс | 0 |
| 390 × 844 | 148 мс | 124 мс | 0 |

Это лабораторные наблюдения в облачной среде, а не оценка пользовательских Core Web Vitals. На desktop последним LCP-кандидатом был текст заголовка с существующим проявлением, на mobile — `club-photo`. Небольшая разница времени не доказывает ускорение или замедление в реальных условиях. В экспериментальных запусках зафиксировано по одной long task на набор из пяти запусков: максимум 56 мс desktop и 50 мс mobile; в базе такие задачи также присутствуют.

HTML увеличился с 34 358 до 43 508 байт без сжатия (+9150 байт). Новых сетевых ресурсов нет. При реальном ограничении сети через CDP до 64 000 байт/с и задержке 200 мс эффект был пропущен около 1500 мс, фото успешно загрузилось позднее с обычным освещением. Изображение не удерживается скриптом.

Данные: [поведение](previews/club-awakens-v1.1/behavior-verification.json), [геометрия и координаты](previews/club-awakens-v1.1/capture-verification.json), [пиксели](previews/club-awakens-v1.1/pixel-comparison.json), [производительность](previews/club-awakens-v1.1/performance.json), [параметры MP4](previews/club-awakens-v1.1/video-verification.json).

## Локальный просмотр

В локальной копии ветки `experiment/club-light-entrance` запустите из корня репозитория:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8000/`. Обновление запускает вступление заново. Сравнения:

- `http://127.0.0.1:8000/?clubLights=off`
- `http://127.0.0.1:8000/?warmWelcome=off`
- `http://127.0.0.1:8000/?clubLights=off&warmWelcome=off`

Для воспроизведения QA используйте Playwright, Chromium, Python/Pillow и ffmpeg/ffprobe; странице эти зависимости не нужны. Запустите локальный сервер на 8794 и по порядку выполните `node docs/qa/verify-club-awakens.cjs`, `node docs/qa/capture-club-awakens.cjs`, `python3 docs/qa/compare-club-awakens.py`, `node docs/qa/measure-club-awakens.cjs`, `node docs/qa/record-club-awakens.cjs`. При необходимости задайте `PRIVATE_CLUB_PLAYWRIGHT_MODULE` и `PRIVATE_CLUB_CHROMIUM_EXECUTABLE`. Чистый запуск без `CLUB_LIGHTS_QA_RESUME` выполняет все проверки.
